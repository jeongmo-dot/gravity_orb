# 구현 로드맵 — 가칭 「그래비티 오브」

> 기준 문서: `gravity_orb_design.md` (기획서 v0.1)
> 엔진: Godot 4.x 최신 안정판 · 언어: GDScript (타입 명시)
> 순서: **PC에서 재미 검증 → 모바일(Android 우선) 포팅**

---

## 0. Codex 작업 지침 (모든 마일스톤 공통)

- **한 번에 한 마일스톤만** 구현한다. 다음 마일스톤 기능을 미리 넣지 않는다.
- 각 마일스톤은 **완료 조건**을 모두 만족해야 끝난 것으로 본다.
- 밸런스 수치(반지름, 확률, 점수, 임계값 등)는 코드에 하드코딩하지 않고 **`GameConfig` 리소스(.tres)** 에서 읽는다.
- 입력은 반드시 **입력 추상화 계층**을 거친다. 게임 로직은 키보드·마우스·터치를 직접 알지 못한다. (모바일 포팅 대비)
- 화면은 처음부터 **세로 비율**로 만든다. PC에서도 세로 창으로 테스트한다.
- 물리 콜백 안에서 노드를 삭제·생성하지 않는다. `call_deferred` 또는 턴 처리 단계에서 일괄 처리한다.
- 무작위는 **시드 고정 가능한 RNG** 하나만 사용한다. (버그 재현용)

### 권장 폴더 구조
```
res://
├─ config/        GameConfig.gd, default_config.tres
├─ scenes/        Main.tscn, Board.tscn, Orb.tscn, UI.tscn
├─ scripts/
│   ├─ input/     InputRouter.gd
│   ├─ core/      TurnManager.gd, CollisionResolver.gd, Spawner.gd, ScoreManager.gd
│   └─ debug/     DebugOverlay.gd
└─ assets/
```

## M0. 프로젝트 셋업

**목표**: 빈 프로젝트가 세로 화면으로 PC에서 실행된다.

- Godot 4.x 프로젝트 생성, 위 폴더 구조 생성
- 기준 해상도 1080×1920, stretch mode `canvas_items`, aspect `keep`
- PC 실행 시 창 크기 540×960 (세로)
- `GameConfig` 리소스 스크립트와 기본값 파일 생성 (필드는 이후 마일스톤에서 추가)
- git 저장소 초기화, `.gitignore`에 `.godot/` 포함

**완료 조건**
- [ ] 실행하면 세로 창에 빈 화면이 뜬다
- [ ] 창 크기를 바꿔도 비율이 유지된다

## M1. 보드와 구체 물리

**목표**: 구체들이 보드 안에서 지정한 방향의 중력으로 굴러간다.

- 정사각형 보드 + 4면 벽 (StaticBody2D)
- `Orb.tscn`: RigidBody2D + 원형 CollisionShape2D, 속성 `color`, `level`
  - 레벨에 따라 반지름 = `r0 × growth^(level-1)` (config 값 사용)
  - 색은 임시로 단색 원 그리기
- 중력 처리: 구체의 `gravity_scale = 0`, 매 물리 프레임 현재 중력 방향으로 힘을 가한다 (방향 전환 제어를 쉽게 하기 위함)
- 임시 입력: 방향키로 중력 방향 변경 (M2에서 교체)
- 시작 시 테스트용 구체 5개 무작위 배치

**완료 조건**
- [ ] 방향키 4개로 중력이 바뀌고 모든 구체가 그 벽으로 굴러간다
- [ ] 구체가 벽을 뚫거나 보드 밖으로 나가지 않는다
- [ ] 레벨이 다른 구체의 크기가 눈에 띄게 다르다

## M2. 입력 추상화

**목표**: 키보드·마우스·터치가 모두 같은 신호로 들어온다.

- `InputRouter` (오토로드): `swipe(direction: Vector2i)` 시그널 하나만 외부에 제공
- 지원 입력
  - 키보드: 방향키, WASD
  - 마우스: 드래그 (최소 거리 이상 + 주 방향 성분 우세)
  - 터치: 스와이프 (마우스와 같은 판정 로직 공유)
- 스와이프 최소 거리, 방향 판정 비율은 config 값
- 보드 밖 영역에서도 스와이프 인식
- `set_locked(bool)`: 잠금 중에는 시그널을 보내지 않음

**완료 조건**
- [ ] 키보드, 마우스 드래그 모두로 중력 전환이 된다
- [ ] 프로젝트 설정의 "마우스로 터치 에뮬레이션"을 켜도 정상 동작한다
- [ ] 짧은 클릭·대각선 애매한 드래그는 무시된다
- [ ] 게임 로직 스크립트에 `Input.` 직접 호출이 없다

---

## M3. 턴 상태 머신

**목표**: 스와이프 → 물리 진행 → 안정 → 다음 입력의 흐름이 명확히 구분된다.

- `TurnManager` 상태: `WAITING_INPUT → SPAWNING → SIMULATING → CHECK_GAMEOVER → WAITING_INPUT` (기획서 0.2: 스와이프 순간 생성)
- 스와이프 수신 시 입력 잠금, 중력 전환, `SIMULATING` 진입
- 안정 판정: 모든 구체 속도가 임계값 이하인 상태가 N프레임 연속 유지
- 최대 대기 시간 초과 시 강제 안정 (config 값, 기본 3초)
- 현재 중력과 같은 방향 스와이프 허용 여부를 config 토글로 제공 (기획서 7장 미정 사항)
- 이 단계에서 `SPAWNING`, `CHECK_GAMEOVER`는 즉시 통과하는 빈 단계

**완료 조건**
- [ ] 구체가 굴러가는 동안 입력이 무시된다
- [ ] 멈추면 다시 입력이 받아진다
- [ ] 계속 흔들리는 상황에서도 최대 대기 시간 후 턴이 넘어간다
- [ ] 디버그 텍스트로 현재 상태가 화면에 표시된다

---

## M4. 구체 생성

**목표**: 매 턴 중력 반대편 벽에서 새 구체가 들어온다.

- `Spawner`: 중력 반대편 벽을 따라 무작위 위치에 레벨·색을 뽑아 생성
  - 레벨 확률, 색 확률은 config 값
- 다음 구체 미리 뽑아두기 + 화면 상단에 미리보기 표시
- 생성 위치 방식 토글: 무작위 / 벽 중앙 고정 (기획서 7장 미정 사항)
- RNG 시드를 config 또는 디버그에서 지정 가능
- 게임 시작 시 초기 구체 2개 (M1의 테스트용 5개 대체)

**완료 조건**
- [ ] 아래로 스와이프하면 위쪽 벽에서, 왼쪽이면 오른쪽 벽에서 생성된다
- [ ] 미리보기와 실제 생성 구체가 일치한다
- [ ] 같은 시드로 시작하면 같은 순서로 생성된다

---

## M5. 합체 규칙

**목표**: 같은 색·같은 레벨 구체가 부딪히면 한 단계 큰 구체가 된다.

- 구체에 `contact_monitor` 활성화, 충돌 이벤트를 `CollisionResolver`에 전달
- 합체 처리
  - 두 구체 모두 "처리 예정" 표시 → 한 구체가 동시에 두 번 합체되지 않게 함
  - 두 구체 중간 지점에 레벨+1 구체 생성, 속도는 두 구체의 평균
  - 삭제·생성은 지연 처리
- 최대 레벨끼리 합체 시 둘 다 소멸 (보너스는 M7에서)
- 합체 후 새 구체가 다시 합체되면 **연쇄**로 카운트 (턴 내 연쇄 수 저장)

**완료 조건**
- [ ] 같은 색·같은 레벨만 합체되고, 다른 조합은 튕기기만 한다
- [ ] 세 개가 동시에 붙어도 오류나 중복 합체가 없다
- [ ] 연쇄가 일어나면 턴 내 연쇄 수가 올라간다 (디버그 표시)
- [ ] 합체 중에도 턴 상태 머신이 정상적으로 안정 판정을 한다

---

## M6. 상극 소멸

**목표**: 상극 색 구체가 부딪히면 사라진다.

- 색 관계를 config의 **상극 쌍 목록**으로 정의 (기본: 빨강↔파랑)
- 소멸 규칙 A/B/C안을 config 토글로 제공 (기획서 3.5)
  - A: 레벨 무관 둘 다 소멸 (기본)
  - B: 같은 레벨일 때만 소멸
  - C: 큰 쪽이 레벨 차이만큼 남음
- 소멸도 연쇄 카운트에 포함
- M5와 같은 중복 처리 방지 로직 공유

**완료 조건**
- [ ] 빨강↔파랑 충돌 시 규칙에 맞게 소멸한다
- [ ] 초록은 어떤 색과도 소멸하지 않는다
- [ ] 토글을 바꾸면 재시작 없이 다음 충돌부터 규칙이 바뀐다 (디버그 편의)

---

## M7. 게임오버와 점수

**목표**: 한 판이 시작부터 끝까지 성립한다.

- 게임오버·경고: **보류** (기획서 0.2 5.1 — 조건 재설계 전까지 게임오버 없이 계속 쌓인다). 조건이 정해지면 `CHECK_GAMEOVER`에서 판정
- `ScoreManager`: 기획서 5.2 규칙 (합체, 소멸, 최대 레벨 보너스, 연쇄 배수)
- 최고 점수 로컬 저장 (`user://`)
- 게임오버 화면: 점수, 최고 점수, 최대 연쇄, 재시작 버튼 (키보드 R로도 재시작)

**완료 조건**
- [ ] 한 판을 끝까지 플레이할 수 있다
- [ ] 점수가 기획서 규칙대로 계산된다
- [ ] 재실행해도 최고 점수가 유지된다

---

## M8. 피드백과 UI

**목표**: 무슨 일이 일어났는지 눈과 귀로 읽힌다.

- 중력 방향 화살표 + 보드 테두리 강조
- 중력 전환 시 보드가 살짝 기우는 연출
- 합체: 스케일 튀김 애니메이션 / 소멸: 파편 파티클
- 연쇄: "n연쇄" 텍스트, 연쇄마다 임시 효과음 음높이 상승
- 연쇄 순간 짧은 히트스톱 (시간값 config)
- 경고 상태: 생성 쪽 벽 붉게 점멸
- 색각 접근성: 색마다 문양 (빨강 ▲, 파랑 ●, 초록 ■)

**완료 조건**
- [ ] 소리를 끄고도 합체와 소멸이 구분된다
- [ ] 색을 흑백으로 봐도 구체 색이 구분된다
- [ ] 연출이 턴 처리 타이밍(안정 판정)을 깨지 않는다

## M9. 디버그·밸런스 도구

**목표**: 플레이테스트 중 규칙과 수치를 빠르게 바꿔본다.

- 디버그 오버레이 (F1 토글): 턴 상태, 구체 수, 연쇄 수, 시드, FPS
- 디버그 조작
  - 클릭 위치에 지정 색·레벨 구체 생성
  - 보드 초기화, 시드 지정 재시작
  - 한 턴씩 진행하는 스텝 모드
- 미정 사항 토글을 화면 패널에서 변경 (같은 방향 스와이프, 소멸 A/B/C, 생성 위치)
- 주요 물리 수치(마찰, 반발, 반지름 증가율, 보드 크기) 실시간 조절
- 한 판 기록 로그: 턴 수, 점수, 최대 연쇄, 최고 레벨 (CSV로 `user://` 저장)

**완료 조건**
- [ ] 코드 수정 없이 기획서 7장의 미정 사항을 모두 바꿔 테스트할 수 있다
- [ ] 릴리스 빌드에서는 디버그 기능이 비활성화된다

## M10. 모바일 포팅 (Android 우선)

**목표**: 실제 폰에서 PC와 같은 경험을 한다.

- Android export 설정, 실기기 테스트 빌드
- 터치 스와이프 판정값을 실기기 기준으로 재조정
- 세이프 영역(노치·내비게이션 바) 대응 UI 배치
- 스와이프 시 짧은 진동 (설정에서 끄기 가능)
- 앱 백그라운드 진입 시 자동 일시정지, 복귀 시 이어하기
- 성능: 구체 최대 개수 상황에서 60fps 유지 확인, 필요 시 파티클·물리 반복 수 조정
- 게임 도중 종료해도 현재 판 저장 여부 결정 (선택)

**완료 조건**
- [ ] 저사양 기준 기기에서 프레임 저하 없이 한 판 플레이 가능
- [ ] 한 손 세로 조작으로 모든 기능 사용 가능
- [ ] 스와이프 오입력(의도와 다른 방향)이 체감상 거의 없다
